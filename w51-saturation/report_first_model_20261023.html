W51 saturated-pixel recovery: first model¶

2026-10-23

Data. The v4 training set (making_training_set.py at 5ae34be: fit design B, PSF evaluated at each star's position, bad-pixel cluster rule, MIRI science-area rule), assembled by py/assemble_training_set.py:

  • rows with psf_share > 0.75 and area_ratio <= 16 (NIRCam) or <= 4 (MIRI) (report_area_ratio_gallery_20261023.ipynb);
  • at most 30 rows per star and exposure, core pixels (low sat_level) first;
  • features: the ramp (DN0-DN4, slopes, curvatures, nl_strength, max_DN, mean_DN, MIRI step ratios, NIRCam zeroframe_rate), sat_level, filter, instrument, detector, 4QPM pane, the saturation-mask geometry (sat_area, sat_depth, distance to the mask centre and its ratio to the region's radius, numbers of level-0 and level-0/1 pixels), local_bkg and the level-0 type. Nothing that needs the PSF fit.

Model. One XGBoost model for NIRCam and MIRI together (py/train_model.py; 800 trees, depth 8, learning rate 0.05), predicting log10 of the target. Two targets: label (the PSF label everywhere) and label_hybrid (the pipeline value at sat_level 2-4, the PSF label at 0-1).

Evaluation. 5 folds split by sky position (one star, across exposures and filters, is never on both sides); a held-out set of the brightest 20% of stars per filter; three baselines (median label per filter and level; a linear fit on DN0 per filter; the same model trained without level 0); and a shuffle test (level-0 ramp features permuted within each filter). Errors are in dex: the half-width of the 16-84% range of log10(prediction / label). The labels themselves are uncertain by about 0.12 dex (NIRCam short wave), 0.21 dex (long wave) and 0.28 dex (MIRI) (report_label_validation_20261022.ipynb); a model cannot be shown to do better than that.

def table(m, preds, by):
    t = m[m.pred.isin(preds) & m[by].notna()].copy()
    t['score'] = t.apply(lambda r: f"{r.scatter_dex:.3f} ({r.bias_dex:+.2f}, {r['within_x1.5']:.0%}, {r.slope:.2f})", axis=1)
    return t.pivot_table(index=['inst', by], columns='pred', values='score', aggfunc='first')[preds]

Reading¶

Within the brightness range it was trained on, the model reaches the label noise floor. Cross-validated by sky position:

NIRCam MIRI per-filter median linear fit on DN0
level 0 0.142 dex, unbiased, 75% within x1.5 0.271 dex, 51% 0.54-0.56 0.31 (MIRI) to 0.49 (NIRCam)
level 1 0.110 0.211 0.47-0.56 0.32-0.36
levels 2-4 0.035-0.047 0.16-0.20 0.35-0.54 0.23-0.43

The labels themselves are uncertain by about 0.12-0.21 dex (NIRCam) and 0.28 dex (MIRI), so the level-0 errors are at that floor; nothing finer can be verified with these labels. At levels 2-4 the error is far below the floor because, with fit design B, those labels are fitted to the pipeline values and are smooth; the hybrid target there (the pipeline value itself) is predicted to 0.02 dex (NIRCam) and 0.10 dex (MIRI).

Level 0 by type (NIRCam): A-hard 0.21 dex, A-soft 0.12, B 0.14, C 0.12; MIRI A 0.29, C 0.24. The A-hard pixels, whose ramps carry nothing, still reach 0.21 dex: the spatial features (saturated area, depth, mask centre) carry the star's brightness. The shuffle test permutes ramp features across all level-0 types of a filter, so its A-hard result mixes in other types' ramps; a shuffle within each type would isolate the A-hard case.

Training on level-0 rows matters: without them the NIRCam level-0 error rises from 0.14 to 0.26 dex. The ramp is used: shuffling the level-0 ramp features raises it to 0.63 dex. The most used features are DN0, the filter (bandwidth, wavelength), zeroframe_rate and the early slopes.

The brightest stars are the problem. With the brightest 20% of stars per filter held out, NIRCam level-0 predictions are a factor 10 too low (bias -1.0 dex) and do not follow the label at all (slope -0.04); A-hard pixels are 60x too low. MIRI level 0 is 0.28 dex low. A tree model cannot predict values above the largest it was trained on, and the brightest stars are exactly the ones whose cores need restoring most. Cross-validated scores therefore overstate how well the model would do on a new, brighter star. The test is harsh in one more way: level-0 pixels come almost only from the brightest stars, so the held-out set contains 44,858 of the 47,669 NIRCam level-0 pixels (94%), and that model was trained with almost no level-0 pixels at all. The model trained without level 0 but on stars of every brightness (0.26 dex, slope 0.80) shows that seeing bright stars at other levels already helps a lot; what fails is going beyond the brightest star seen.

What to try next (none tried yet):

  1. A scale-free target. Predict the label divided by a brightness reference that is available without a PSF fit, for example the mean of the unsaturated ring around the saturated region, or the saturation threshold rate of the pixel. The model then learns a shape, which does not need extrapolation.
  2. Brightness-aware features. Give the model quantities that grow with the star's brightness beyond the training range (ring flux, saturated area, number of group-0 pixels) in a form a tree can use, or combine the tree with a linear term in log brightness.
  3. For A-hard pixels, use the PSF fit itself where the star's wings can be fitted, and the model only where they cannot.
  4. Report the bright hold-out as the main score from now on, next to the cross-validated one.
