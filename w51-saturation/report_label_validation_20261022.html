W51 saturated-pixel recovery: label validation¶

2026-10-22

Question. A label is a PSF fit's prediction for a pixel the fit could not use. How good are those predictions, and which way of fitting gives the best ones? The question became urgent when the fit mask turned out never to have masked the saturated pixels (discussion_20261022.ipynb, section 0).

Method (py/validate_labels.py, job 47209741). For every star kept by the pipeline in 28 exposures, the star is refitted several times with different masks, and each fit predicts pixels whose pipeline value (cal) is a real measurement: the star's sat_level-2 pixels, which keep 2 unsaturated groups.

fit masked what it tests
A every flagged pixel (+1 px) the original design: the fit sees only the wings
B the star's pixels without a valid slope (sat_level 0-1, +1 px); its sat_level 2-4 pixels are fitted as data the alternative design
hold0-hold3 the star's sat_level 0-2 pixels, + 1 to 4 px predicts the held-out level-2 pixels from data 1-4 rings further out: how error grows with the extrapolation distance
centre shifts as A or B, centre fixed at +-0.1 px in x and in y how sensitive core labels are to the fitted centre

hold0 is the honest stand-in for design B: B predicts the sat_level 0-1 core from the level-2 ring around it, and hold0 predicts the level-2 ring from the level-3 ring around it.

Sample: NIRCam short wave (F182M nrcb1 x4, F210M nrcb4 x2), long wave (F410M nrcblong x4, F335M nrcalong x2), MIRI (F770W, F1280W, F2100W x4; F560W, F1000W x2). Other stars' flagged pixels are masked in every fit.

import glob, os
import numpy as np
import pandas as pd
import matplotlib.pyplot as plt
from astropy.table import Table

D = '/orange/adamginsburg/w51/TaehwaYoo/w51_sat_recover/label_validation'
BAND = {'F182M': 'NIRCam SW', 'F210M': 'NIRCam SW', 'F410M': 'NIRCam LW', 'F335M': 'NIRCam LW'}

def load(kind):
    out = []
    for fn in sorted(glob.glob(f'{D}/*_{kind}.fits')):
        t = Table.read(fn)
        if len(t) == 0:
            continue
        d = t.to_pandas()
        for c in d.columns:
            if d[c].dtype == object:
                d[c] = d[c].str.decode('utf-8') if isinstance(d[c].iloc[0], bytes) else d[c]
        d['filter'], d['exposure'] = t.meta['FILTER'], t.meta['EXPOSURE']
        d['band'] = BAND.get(t.meta['FILTER'], 'MIRI')
        out.append(d)
    return pd.concat(out, ignore_index=True)

1. Predicting pixels the fit cannot see¶

For held-out sat_level-2 pixels: the ratio prediction / cal. 1 is perfect.

held = pix[pix.set == 'held'].copy()
variants = ['A', 'hold0', 'hold1', 'hold2', 'hold3']
def summary(d, by):
    rows = []
    for key, g in d.groupby(by):
        for v in variants:
            r = (g[f'pred_{v}'] / g.cal).replace([np.inf, -np.inf], np.nan).dropna()
            if len(r) < 5:
                continue
            rows.append({**dict(zip([by] if isinstance(by, str) else by, [key] if isinstance(by, str) else key)), 'fit': v, 'pixels': len(r),
                         'stars': g.loc[r.index].source_index.astype(str).add(g.loc[r.index].exposure).nunique(),
                         'median': round(r.median(), 3), '16%': round(r.quantile(.16), 3), '84%': round(r.quantile(.84), 3),
                         'off by > x1.5': f'{((r < 0.67) | (r > 1.5)).mean():.0%}'})
    return pd.DataFrame(rows)

2. Sensitivity to the fitted centre¶

Core pixels (sat_level 0): how much the label changes when the centre is fixed 0.1 px away from the best fit, for fits A and B. For each pixel the largest of the four shifts is taken.

3. The same star in different dithers¶

Stars matched across the exposures of one filter (fitted centres within 0.3 arcsec). For each star with at least 2 exposures: each exposure's fitted flux divided by the star's median. The spread is a lower limit on the label error that does not depend on the pipeline's cal values.

from astropy.coordinates import SkyCoord
import astropy.units as u
rows = []
for F, g in stars.groupby('filter'):
    g = g.dropna(subset=['ra', 'dec']).reset_index(drop=True)
    c = SkyCoord(g.ra.values * u.deg, g.dec.values * u.deg)
    # one star = connected detections closer than 0.3 arcsec
    from scipy.sparse.csgraph import connected_components
    from scipy.sparse import coo_matrix
    i, j, d2, _ = c.search_around_sky(c, 0.3 * u.arcsec)
    n, comp = connected_components(coo_matrix((np.ones(len(i)), (i, j)), shape=(len(g), len(g))))
    g['star'] = comp
    for v in ['A', 'B']:
        f = g.groupby('star')[f'flux_{v}']
        ratio = (g[f'flux_{v}'] / f.transform('median'))[f.transform('size') >= 2]
        ratio = ratio[np.isfinite(ratio) & (ratio > 0)]
        if len(ratio):
            rows.append({'filter': F, 'band': g.band.iloc[0], 'fit': v, 'stars seen >= 2 times': int((g.groupby('star').size() >= 2).sum()),
                         'detections': len(ratio), 'scatter (16-84% half-width)': f'{(np.percentile(ratio, 84) - np.percentile(ratio, 16)) / 2:.1%}'})
pd.DataFrame(rows).set_index(['band', 'filter', 'fit'])

Reading¶

The labels are less accurate than the v3 check suggested. Where a label can be tested against an independent measurement (held-out sat_level-2 pixels):

band design A (wings only) hold0 (stand-in for design B) as a log error (B)
NIRCam short wave median 1.05; 16-84% 0.81-1.40; 18% off by > x1.5 1.04; 0.81-1.39; 18% about 0.12 dex
NIRCam long wave 1.20; 0.82-2.43; 43% 1.18; 0.85-2.27; 38% about 0.21 dex
MIRI 0.98; 0.57-3.09; 64% 1.03; 0.59-2.17; 56% about 0.28 dex

These are a floor for any model trained on the labels: a model cannot be checked against labels more precisely than the labels themselves. (For comparison, the feature subagent's first models reached 0.15 dex at NIRCam level 0, already close to this floor.)

Where the error comes from.

  • Extrapolation distance matters for NIRCam long wave and MIRI: moving the nearest fitted data 1 -> 4 rings away raises the outlier fraction from 38% to 59% (long wave) and 56% to 75% (MIRI). For NIRCam short wave it barely matters (18% throughout), so the error there sits elsewhere.
  • The fitted centre matters everywhere: a shift of only 0.1 px changes core labels by a median 8-15% (84th percentile 17-24%). The core of a star is steep, and with the core masked the centre is less certain than that.
  • The PSF model has no brighter-fatter effect and a fixed core shape; the BFE subagent measured the real cores 1% (NIRCam SW), 4-5% (LW) and 8-22% (MIRI) lower than the first ring relative to the model.
  • The test's own truth is a 2-group slope; near-saturation non-linearity and charge pushed into neighbours of saturated pixels can bias it. Part of the scatter may therefore be in cal, not in the label.

Total star fluxes are robust. The same star in different dithers agrees to 2-5.5% with design A and 0.5-2.3% with design B. The weak point is the distribution of that flux over the core pixels, not the total.

Design B is better in every test. Slightly in the hold-out test, clearly in repeatability (NIRCam long wave: 1.3% against 5.0%). At the core, B's labels are a median 1% (NIRCam) and 15% (MIRI) above A's.

Recommendations.

  1. Use design B for the labels: fit every pixel that has a valid measurement, mask only the sat_level 0-1 core.
  2. Treat these numbers as the label noise floor when judging models; report model errors against it.
  3. For sat_level 2-4, prefer cal_value as the target (a direct measurement).
  4. For MIRI, treat level 0-1 labels as uncertain by about a factor 2.
  5. To improve labels further: an empirical PSF built from W51's own unsaturated stars (real core shape, including part of the BFE), and finer PSF oversampling for NIRCam short wave, where the PSF is barely sampled.

Limits. MIRI has only 51 stars with held-out pixels; the smallest-area bins hold few stars; the hold-out test uses sat_level-2 pixels as the truth, which are one ring outside the level 0-1 core that the labels are for.
